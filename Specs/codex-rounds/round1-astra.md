**Round 1 verdict: revise before implementation.** The proposal has a schema collision, a public-storage mistake, incompatible audio assumptions, incomplete money recovery, and an underspecified capacity authority.

Read-only audit; no files changed, builds run, or live configuration inspected. Telemetry was unnecessary for this static review. References below use repository-relative `file:line`.

## 2. Design risks, ranked by severity

| Severity | Risk | Concrete fix |
|---|---|---|
| **Critical** | **Capacity admission is not specified as an executable atomic operation.** | D1 batches **are transactional**; it would be incorrect to say otherwise. But JavaScript cannot inspect a SELECT and conditionally add a DELETE inside an already-submitted batch. Entirely SQL-side conditional admission can be atomic; post-batch compensation is outside that transaction. [D1 documentation](https://developers.cloudflare.com/d1/worker-api/d1-database/). |
| **Critical** | **Per-agent admission alone cannot enforce the global cap.** | For this small initial cap, use one platform seat-authority DO with SQLite transactions covering both global and per-agent schedules. Alternatively, use per-agent authorities plus a global lease coordinator with explicit compensation. Booking-room DOs enforce the returned lease; D1 stores projections/audit records. `transactionSync` supplies a local transactional primitive, not a transaction across DOs or WalletDO. [DO storage documentation](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/). |
| **Critical** | **Money can be stranded, over-refunded, or marked settled prematurely.** | Persist a checkout operation before any debit, keyed by buyer plus idempotency key and request hash. Persist one immutable settlement decision per order. Serialize release/refund decisions; use deterministic operation IDs and retry jobs. Only mark settlement complete after every required leg succeeds. Different refund IDs do not prevent their combined amount exceeding escrow. |
| **Critical** | **Private transcripts/photos could become public.** | Use `DIGITAL` or a dedicated private bucket, never public `BLOBS`. Authorize each read against buyer/session ownership; use short-lived URLs only when needed. Never copy the old DO’s owner Inbox transcript delivery (`agent_voice_room.ts:597–628`) into private companion calls. |
| **High** | **Counting overlapping rows is not peak concurrency.** | Evaluate occupancy at interval boundaries. With cap two, bookings `[0,10)` and `[10,20)` allow another `[0,20)` booking; counting both as simultaneous falsely rejects it. Process ends before starts at equal timestamps. Include provisional reservations and runtime leases. |
| **High** | **Booking and runtime reservations disagree.** | Separate prejoin from provider start. Connecting at `starts_at−2min` must not consume unreserved capacity. Do not admit based on a 90-second heartbeat count: stale does not prove the provider stopped. Use expiring, fenced leases; close the old provider connection before reusing capacity. Count admin tests and other users of the same provider allocation. |
| **High** | **Early release and reconnect can sell the same time twice.** | Define explicit “end permanently” versus temporary disconnect. During reconnect grace, retain the reservation and original deadline. Once permanently released, reject old room tokens. An early end permits a new booking only if its **whole requested interval** fits; it does not move another customer’s scheduled start automatically. |
| **High** | **Refund/no-show rules are invented rather than inherited.** | Add an AI-specific rulebook section. Existing platform-failure rule C4 is a full refund (`Specs/RULEBOOK-PAID-SESSIONS.md:59`); the proposed after-30-second partial refund is a new exception. Define service-availability evidence before charging no-shows, cancellation inside ten minutes, provider setup failure, silent audio, partial outages and user disconnects. |
| **High** | **Full release followed by unused-time refund is contradictory.** | Decide `refund_amount` first; release only `amount−refund_amount`. Persist the exact fee, recipient UID, price, policy version and rounding decision. Refund seconds or explicitly define whole-minute rounding; do not disguise undelivered fractions as delivered service. |
| **High** | **Join links confer account-wide authentication.** | Current `/j` mints a full Clerk sign-in ticket (`join_link.ts:129`), not a booking-only credential. Prefer a reusable booking-scoped guest capability for this lane. If full Clerk authentication remains, document that security consequence, prevent token leakage, rate-limit redemption and require stronger authentication for privileged actions. Fail closed without a signing secret: existing code falls back to `dev-join-secret` (`ics.ts:78,98`). |
| **High** | **Memory creates persistent injection and deletion races.** | Treat transcripts, RAG and extracted facts as untrusted data. Enforce tool permissions outside prompts. Bound every field and total prompt budget; attach provenance and memory versions. Serialize/CAS concurrent updates. “Forget me” increments an erasure generation so an active call or delayed summarizer cannot recreate deleted memory. |
| **High** | **Email-based administrative access widens privilege and redirects earnings.** | Use a dedicated immutable UID allowlist/capability shared by create, edit, publish, KB and test endpoints. Resolve verified email to UID during provisioning. Keep the earnings beneficiary separate from the administrator performing an edit. Do not publish an admin email list through public `/api/config` (`config.ts:2614`). |
| **High** | **Unbounded image/RAG/tool use defeats the price floor.** | Add per-session/user limits on image count, decoded pixels, tool calls, backend tokens and spend. Validate actual file bytes, strip metadata, reject malformed images and constrain analysis output. Bind jobs to session generation; discard late results after end/forget. Never expose arbitrary R2 keys or URLs to model-controlled tools. |
| **High** | **Minors and sensitive companion interactions have no enforcement contract.** | Define allowed personas and age policy before launch. Enforce `adults_only` server-side at booking and join, including guest customers; reconcile its duplicate persona/listing fields. Add AI/transcription disclosures, reporting, abuse handling and boundaries for dependency, sexual content and medical claims. An entertainment sentence alone is insufficient. |
| **Medium** | **A DO PCM relay is assumed preferable to WebRTC without comparison.** | Evaluate browser→OpenAI WebRTC with a server-created session and DO sideband control. It keeps the key server-side while using native media transport. If choosing the relay, specify chunk aggregation, backpressure, jitter limits, interruption handling, mute/silence behavior and browser audio recovery. OpenAI documents WebRTC for browsers and WebSockets for server audio. [Connection guidance](https://developers.openai.com/api/docs/guides/live). |
| **Medium** | **Socket uptime is treated as delivered service and authoritative final usage.** | Separate scheduled entitlement, provider usage and audible delivery. Persist readiness, first audio, outages and cumulative usage. Close with `session.close`, drain `session.closed`, and mark missing final usage unconfirmed. Reconcile rather than silently declaring success. [Session lifecycle](https://developers.openai.com/api/docs/guides/live-conversations). |

## 3. Missing pieces

- **Durable lifecycle:** reservation expiry, abandoned checkout, startup timeout, no-show settlement, stuck-session and refund sweeps; retry backoff, dead-letter handling and operational alerts. Alarms plus cron backstop must work even when no browser ever connects.
- **Schema contract:** distinct table names; foreign keys/check constraints; immutable policy/persona versions; beneficiary snapshot; checkout/settlement jobs; consent/erasure versions; `image_instructions`, which the UI requires but the schema omits.
- **Privacy lifecycle:** separate “disable future memory” and “erase history”; delete transcripts, images, analyses, cached context and provider-held objects; integrate account deletion/export and define retention/backup treatment. The existing deletion handler targets legacy `agent_personas.uid` (`consumers/src/deletion.ts:342`).
- **RAG lifecycle:** asynchronous indexing, retries, readiness checks, content-hash deduplication, deletion reconciliation, document limits and retrieval access control. Uploading documents is retrieval setup, not model training.
- **Payment integration:** server quotes, funding-rail identity, gateway callbacks, refund destination, receipts, tax/fee policy and affiliate treatment. Existing direct gateway funding uses `holdExternal`, not wallet top-up (`ledger.ts:60–87`).
- **Flags:** separate checkout shutdown from new-call shutdown and emergency termination; define treatment of paid bookings when disabled. Add bounded string/numeric validation and explicit model/slot precedence between flags and persona fields. Keep refunds, receipt access and erasure available when the lane is off.
- **Client coverage:** canonical pretty URLs, shared detail component, web taxonomy, Flutter remote-config gating, correct audio-only labels, account switching and stale-cache behavior.
- **Telemetry:** never collect transcripts, image analyses, prompts or join tokens. Replace heuristic URL scrubbing for `/j/<token>`: `apiClient.ts:20–28` does not reliably recognize dotted bearer tokens. The proposed success check requires `agent_talk_ready.outcome`, but that event’s declared payload omits it.
- **Policy and rollout:** explicitly scope an AI exception to the GetStream-only paid-media rule (`CLAUDE.md:462–475`). Keep the lane dark until deployed surfaces and paid failure tests pass. Replace bare `wrangler secret put` with the wrapper; the proposed production migration command also lacks `ALLOW_PROD=1` (`scripts/cf.sh:73`).

## 4. Recommended spec changes

1. Rename all new tables consistently to `agent_live_*`; preserve existing agent tables.
2. Replace the count-based seat sketch with a transactional authority covering **both caps**, provisional reservations, fenced runtime leases and recovery.
3. Specify checkout and settlement state machines with deterministic IDs, immutable amounts and durable compensation.
4. Add an owner-approved AI-session money matrix, including availability evidence for no-shows and refunds for platform failures.
5. Move all customer content to private storage and define consent, retention, export and race-safe erasure.
6. Replace “reuse as-is” with explicit adaptation requirements for audio, prompts, concurrency, settlement and finalization.
7. Correct the Live contract: shared audio rate, caller transcript events, backend instruction updates, supported RAG integration and graceful close.
8. Choose WebRTC versus relay using latency, interruption, recovery and operating-cost evidence.
9. Use UID-based lane administration and a separately frozen earnings beneficiary.
10. Extend the entire join-token/authentication chain, preferably with booking-scoped access.
11. Complete flags, schemas, shared web surfaces, Flutter gating and bounded abuse/cost controls.
12. Require acceptance tests for simultaneous bookings, duplicate checkout, queue lag, crash-after-hold, competing refunds, reconnect takeover, provider outage, cross-account reads and forget-during-summary before enabling sales.
