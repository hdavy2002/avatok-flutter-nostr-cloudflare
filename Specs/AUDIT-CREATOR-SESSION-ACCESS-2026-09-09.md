# Creator streaming, appointments and attendee access audit

Date: 2026-09-09. Scope: production, read-only audit; no application changes, deployment, build, purchases, invitations or camera sessions.

## Assessment

The media and payment foundations exist, but the complete purchase → email → open → correct room journey is not ready. Fix admission and navigation contracts before treating either paid experience as launch-ready. Most work is integration and repair; a browser livestream host console is a new UI build.

## Proposed sidebar and screen ownership — app and website

| Menu | Who uses it | What it opens | Primary action |
|---|---|---|---|
| Marketplace | Everyone | Discover/book creators and events | Buy ticket / Book appointment |
| My Tickets & Appointments | Customers, including creators who purchase | Purchased live events and booked 1:1 sessions; Upcoming / Live now / Past | Watch event / Join appointment |
| Creator Studio → My Live Events | Creators | Scheduled broadcasts, time, ticket sales, readiness and state | Test camera → Enter backstage → Start live; Rejoin controls if already live |
| Creator Studio → My Appointments | Creators | Exact booking, customer, local date/time, status, preparation | Start/Join that appointment |
| Creator Studio → My Listings | Creators | Offer creation, pricing, availability, publication and edits | Manage offer |
| Calendar | Both roles | Combined schedule with role-specific destination | Open the matching session |

Keep customer bookings outside the web Studio-only grouping. Show creator tools to creators and preserve a discoverable way for new creators to create an offer. A creator who also buys sessions should see both areas. Opening a page must never start broadcasting automatically.

## Delivery plan

1. **Repair room admission and links first:** support real persisted booking IDs, one typed room destination, canonical web paths, existing emailed invites, exact app links, and stable push metadata. Add CI integration coverage using an ID produced by checkout, not short fixture IDs.
2. **Connect fulfilment to email:** enqueue confirmations only after paid/reserved entitlement is durable; separate live-ticket and 1:1 templates; link to the exact event/appointment; include local-time display and calendar attachment. Implement idempotent resend, reliable retry, delivery status and an email-access route that verifies the purchasing account. The invitation locates the booking; it must not bypass entitlement checks.
3. **Expose existing customer rooms:** app sidebar route to My Sessions; replace web legacy booking-only data with the commercial customer projection; label watch vs two-way appointment clearly; preserve loading, early, ended, cancelled, wrong-account and refunded states.
4. **Build creator schedule and browser host controls:** host/creator projection plus dated appointment picker; visible app start controls; web consultation joins reuse ConsultRoomGS; new web livestream host console calls the existing prepare-host/go-live/end authority.
5. **Prove complete journeys before release:** creator app → browser attendee; creator app → app attendee; browser creator → browser/app attendee where supported; paid event with at least two buyers; 1:1 with real generated booking ID; fresh-browser email-code login; installed-app cold/warm link open; correct account switching; refunded/forwarded ticket denied; early arrival, host reconnect and session ending; verify actual remote video/audio and correlated provider lifecycle. Run builds/tests only through authorized GitHub Actions; no build was requested or dispatched in this audit.

## Completion criteria

A paid customer can recover the purchase from the sidebar even if the email is lost. The email opens the same entitled session in a browser without installing the app or in the installed app. The creator sees the correct event/appointment and explicitly starts camera broadcasting. A viewer sees the creator; an appointment allows both parties to see/hear each other. Email, admission, remote-media and session-end evidence can be correlated by stable non-secret IDs. Record engineering audit telemetry separately from real customer success events.
