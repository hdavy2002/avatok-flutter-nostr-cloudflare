# Public UI catalogs

Only authored public interface text belongs here. Never insert account names, private messages, documents, tokens, signed links or runtime user values. Interpolate those values locally after retrieving copy. Existing paid content/call translation is independent.

`locales.json` is the finite registry: English, Hinglish, the 22 scheduled Indian languages, plus Bhojpuri (`bho`) and Awadhi (`awa`). These two additional languages use Devanagari/LTR and their matching Google targets; registering them does not assert translated catalog availability. Arabic is excluded. `ks`, `sd`, `ur` use RTL Arabic script; `mni` uses Meitei and `sat` Ol Chiki. Locale codes preserve existing client preferences. A null Google target requires curated translation, not English relabeled as that language. Google capability is checked at generation time; Bodo/Kashmiri/Santali/Hinglish are never guessed.

`source/{namespace}.json` contains flat authored fallback messages (prefer canonical English; legacy website copy can be Hinglish/Hindi). Namespace and key are stable; source changes invalidate only the changed translations. Namespace sourceHash is SHA-256 of recursively key-sorted compact UTF-8 JSON. Catalog releases are SHA-256 of the entire generated catalog set plus availability/provenance. A missing namespace means use local source copy; it does not mean translation is complete.

`reviewed/{locale}/{namespace}.json` contains `{reviewed, provenance, messages: {key: {source, text}}}`. A translation is reused only when reviewed is true and source exactly matches current source. Legacy landing drafts are retained with reviewed false. Existing chrome's reviewed-key annotation is retained, except Santali's legacy Devanagari copy requires Ol Chiki review. Native language/legal/safety review remains necessary before claiming complete coverage.

## Runtime contract

- `GET /i18n/v1/manifest.json`: `{schemaVersion:1,release,locales:{locale:{namespaces:[],status}},namespaces:[],sourceHashes:{namespace:sha256}}`. Locale status is source, reviewed or machine. The `en` source locale retains authored fallback copy and does not assert mixed legacy copy is all English. All listed namespaces are complete; status machine means at least one contains machine copy. Cache TTL 60 seconds with revalidation.
- `GET /i18n/v1/sources/{sourceHash}/manifest.json`: same manifest, with 60-second TTL. Native clients first request their compiled namespace source hash, then require `sourceHashes.app` to match before selecting a release. Global-manifest fallback is usable only when its app source hash matches. Publication updates pointers for current namespace hashes after immutable objects are verified and retains historical hashes, so an older installed app can discover its last compatible translation release without a preexisting local cache. Unknown hashes are no-store 404; mismatched pointers are rejected.
- `GET /i18n/v1/{release}/{locale}/{namespace}.json`: `{schemaVersion:1,release,locale,namespace,messages,sourceHash}`. Release is 64 lower-case hex characters. Maximum envelope size 2 MiB. Successful responses have ETag and one-year immutable browser/edge caching.
- Existing BLOBS R2 binding uses reserved `ui-catalogs/{prod|staging}/v1/` prefix and physically separate existing environment buckets. Unknown environments fail closed. Worker can only read; misses are no-store 404 and never invoke Google.
- Credentials/cookies/query strings are stripped from edge cache keys. Payloads contain public UI only. Dashboard and authenticated HTML remain private/no-store independently.

## Explicit generation and publication

The manual-only `ui-catalogs.yml` workflow runs generator/Worker tests in CI. No local test/build execution is permitted by project rules. Its default is offline source/reviewed generation with artifact output only. `allow_paid` and a positive attempted-character cap explicitly enable Google NMT with source language auto-detection for mixed authored copy; retries consume the same cap. The one-million-character maximum is a safety ceiling, not authorization to spend it. Google project API enablement, billing, quota and current rate must be checked separately before the first paid dispatch.

Required paid configuration (separate per GitHub environment): secret `UI_TRANSLATION_GOOGLE_SA_JSON`, variable `UI_TRANSLATION_GOOGLE_PROJECT`. Use a dedicated service principal limited to Translation user access in that project. No Google secret is added to the Worker or clients. Batches are bounded to 50 messages/5000 masked characters, HTTP requests time out and 429/5xx and network/timeouts get bounded backoff. Content hashes deduplicate identical source strings; cached successful translations resume subsequent runs, including when the prior job exhausts its cap or fails. The workflow saves provider cache and uploads partial failure reports even after a failed generation step. Generated metrics report request count, attempted characters, elapsed time and missing keys, never private text. Formatted ICU/plural/select strings require reviewed translations and are not sent to NMT. Placeholder, URL, markup and known product-name mutations reject publication.

Publication is separately opt-in (`publish`). Incomplete coverage for any registered locale/namespace is refused unless `acknowledge_partial` explicitly accepts reduced coverage; this can replace a richer prior release and must be reviewed. Required environment secrets: `UI_CATALOG_R2_ACCESS_KEY_ID`, `UI_CATALOG_R2_SECRET_ACCESS_KEY`, with write access limited to the selected catalog bucket; variable `CLOUDFLARE_ACCOUNT_ID`. The existing production GitHub environment approval gate applies. Publisher independently revalidates source hashes, complete keys, placeholders and the entire release content hash, writes immutable objects conditionally, verifies each object, then updates current source-compatibility pointers and atomically replaces the short-lived global manifest pointer last. No Worker/app build or deployment is triggered. Publication never copies staging data into production. Clients continue to source fallback until a release is explicitly published and the Worker route deployed.

Runtime visual/font review, actual Google credentials/billing/capability, R2 publication, cache HIT measurements, native offline behavior and translation completeness are not established by source changes or CI unit tests alone.
